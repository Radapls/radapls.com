# My experience at Wibx Company

My experience at Wibx was a one hundred and eighty degree turn. It was the first company I joined after making my career transition. At Wibx, I learned a lot, not only about technology but also about relationships, living in a new country, learning a new language, and, of course, programming in this decade.

> For me, Wibx was a space for co-creation. There was never a 'no' to trying something new.

From Augmented Reality filters, to system design, to the administrative backoffice, application refactoring, and several, if not many, landing pages.

## Learning to build software, the hard way

My experience as a frontend developer was based on understanding how Angular works as a framework and optimizing its development to work with TypeScript and SCSS as a CSS preprocessor. It was a great challenge, especially because I was not familiar with frameworks and had more experience with HTML, CSS, and JavaScript. This challenge was of great scalability, even more so when coming from a completely different area.

However, I believe that being close to complex concepts such as reactive state, asynchrony, state management, and clean code for architecture made that path an enjoyable experience. I was always accompanied by teamwork, which I consider crucial at the beginning of a programmer's career. While inherent curiosity is great, having a group-guided approach will always be appreciated.

## From translations to the platform core

Nobody arrives building design systems. My first tasks were **translations and CSS adjustments** — small, unglamorous, and perfect: they let me touch the codebase without the risk of breaking it, and learn how the platform was put together one file at a time. The first real deliveries were whitelabel branding: swapping logos, icons, and drawables so each partner got their own app.

From there, the responsibility grew with the trust:

- **The design system turn** — taking over the Figma side, upgrading loose screens into a real shared library (the `wui-` component family), and starting to build UI for both desktop and mobile from it.
- **Desktop: the Business backoffice** — Wibx's main configurator, where the whole platform is operated: campaigns, challenges, the home configurator, roles and permissions per whitelabel.
- **Mobile: the multiplatform app** — the Android and iOS app where all of Wibx's logic lives: wallet, shopping, rewards, onboarding. The place where the design system pays off every single day, on every screen size.

Looking back, each step made the next one possible: you can't build a backoffice without a design system, and you can't ship a whitelabel without both.

### The whitelabel factory

Because the system was built on tokens and configuration, launching a partner stopped meaning "rewrite the app" and started meaning "configure it". I worked on the implementation of many whitelabels, among them:

[Luperyum](https://luperyum.com.br/), [Speedzin](https://speedzin.com.br/), PrimeCircle, Music Lovers, Samba Lovers, Jovem Pan, EsgX, WineX, WomanX, Amplifyq, Boostzone, Bora and Gate0.

Each one with its own branding, modules, and store — all born from the same base.

## Design, my way back in

Before code, there was design — and that was the bridge that made my career change possible. At Wibx I didn't just implement interfaces: I helped decide how they should look, behave, and scale. Little by little, that sensitivity turned into my main contribution to the product.

### The first design system

When I arrived, every screen solved the same problems in a slightly different way. I created the company's **first design system**: a shared language of tokens, typography, spacing, and Angular components that let designers and developers speak the same language — and stopped each new feature from reinventing the wheel.

<details>
	<summary>What the design system covered</summary>

- Color and typography tokens shared between Figma and SCSS
- A base library of reusable Angular components
- Spacing and layout conventions for the backoffice and the app
- Documentation so the system could survive without me

</details>

### SmartForms

The module I'm proudest of. Forms were the most repetitive and error-prone part of the backoffice, so I built **SmartForms**: a module that generates forms from a configuration, with validation and layout handled once, centrally, instead of copy-pasted across dozens of screens. It now lives on both the backoffice and the mobile app.

What started as an internal convenience became a pattern the team kept extending — which is the best compliment a module can get.

## My responsibilities

- Creating new functionalities, as well as maintaining the base code for the backoffice (Business) and the application (Wibx App).
- Working together with the design team to efficiently deliver new functionalities to the core business.
- Managing HTTPS requests with RESTful APIs for the different integration modules.
- Modular refactoring of the business (WBSC).
- Creating landing pages in alignment with the marketing team for the launch of strategies and campaigns.
- Managing the migration from Angular 15 to Angular 20.
